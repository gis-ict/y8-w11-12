Implement, test and debug

Today you practise turning a plan into Python, testing it and fixing errors. On Thursday you use these skills to build your own project in VS Code.

Your design brief: a program for a younger class. It can be a revision quiz, a unit converter or a text game. Each one needs a loop with an if inside it.

By the end of this hour

1I can predict what a program will print before I run it.
2I can follow a loop with an if inside it in pseudocode, a flowchart and Python.
3I can test a program with normal, boundary and invalid inputs.
4I can find and fix syntax and logic errors, and change a program safely.

Teacher notes: start (3 min)

Read the four goals aloud. If students use the voice, they need headphones; otherwise leave Read aloud off and let them press the speaker button on each part.

Hour plan: Part 1 recap (10 min), Part 2 (8), Part 3 (10), Part 4 (12), Part 5 (14), wrap-up (3). There are no scores today: the aim is that every student understands.

Teacher notes: Part 1 recap (10 min)

This is Part 3 of the homework in 10 minutes. Before anyone clicks, ask: "Before you run it, what do you expect it to print?" Wrong predictions are where the learning is: ask why they thought it.

Menu trap: the program rounds to 2 decimal places, so 6.21 not 6.21371. Dragon trap: there are only three doors, so the last line is "Game over", not another Dragon.

Answers. Syntax: missing colon, = instead of ==. Logic: score printed 3 times, lives go below 0. Test data: 10 normal, 0 boundary, -5 invalid, "abc" invalid.

If there is time: Google "10 km to miles" (6.21371) and "-5 km to miles" (Google gives a negative answer instead of rejecting it). Is -5 km valid? Let them argue.

Teacher notes: Part 2 (8 min)

Goal: see nesting. The if runs inside the loop every turn, and the "lives = 0?" check is an if inside an if. Ask: "Which lines run every turn? Which run only when the door is right?"

Ask: "Pseudocode has END IF and END FOR. Where are they in Python?" (Python uses indentation instead.) "What does break do?" (It stops the loop early.)

Students tick this part off after one game where they survive and one that ends in "Game over" (choose right twice).

Teacher notes: Part 3 (10 min)

This is testing: choosing inputs on purpose to reach every branch. The list of replies is their test-case table. Next week they do this with their own users.

  • Quiz: "Vientiane" with a capital V is marked wrong. Ask how a younger pupil would feel, and how to fix it.
  • Converter: 0 is the boundary. Typing "abc" crashes with ValueError. Ask what float() needs. That crash is a bug to fix in their own project.
  • Guessing game: guessing 7 first time, or never, gives different replies. Ask which inputs reach "Out of tries".
